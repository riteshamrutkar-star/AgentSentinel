# AgentSentinel — Backup & Disaster Recovery Runbook

> **Scope**: Operational runbook for database backup, SHA-256 integrity validation, and non-destructive restoration for AgentSentinel control plane data.

---

## 1. Overview & Data Integrity Guarantees

AgentSentinel persists critical security records across 18 tables:
- Core runtime audits (`security_events`, `approvals`, `agent_sessions`, `threat_signals`)
- Behavioral baselines & models (`behavioral_baselines`, `anomaly_reports`)
- Multi-agent identity & delegation records (`agent_identities`, `delegation_tokens`, `provenance_records`)
- Tool governance (`tool_registry`, `execution_history`)
- Attack simulation results (`attack_scenarios`, `attack_simulation_runs`, `security_findings`)
- Research evidence (`research_experiment_runs`, `ablation_results`)
- Operational controls (`api_keys`, `security_alerts`, `schema_migrations`)

All backups generated by `scripts/backup_db.py` produce:
1. Complete JSON database dump of all 18 tables.
2. Accompanying `.sha256` integrity manifest to detect bit rot or unauthorized tampering.

## 2. Taking a Backup

Execute `scripts/backup_db.py`:

```bash
# Standard backup to default backups/ directory
python scripts/backup_db.py

# Specify custom target output path
python scripts/backup_db.py --output-dir /secure/cold_storage/backups
```

## 3. Verifying Backup File Integrity (Checksum Check)

> [!NOTE]
> Checksum verification confirms that the backup artifact has not been corrupted or tampered with at rest (file integrity). **It does NOT prove database equivalence** or guarantee that records can be successfully reconstructed in a live relational database.

Run the checksum verification drill:

```bash
python scripts/restore_db.py backups/agentsentinel_backup_20260916_174439.json --verify-only
```

Expected output:
```text
[OK] SHA-256 Checksum verified: matches manifest hash.
[*] Backup contains 18 tables. Verify only = True
[SUCCESS] Backup file verified successfully.
```

### Prerequisites
1. Ensure the PostgreSQL container or service is healthy.
2. Schema migrations should be current.
3. Stop external traffic to AgentSentinel during restoration.

### Step 1: Execute Restoration
```bash
python scripts/restore_db.py backups/backup_agentsentinel_20260912_113845.json
```

The restoration tool:
- Validates the SHA-256 signature against the `.sha256` file.
- Reads table records in order of dependency.
- Performs an idempotent `merge` / `upsert` so existing records are preserved and missing records are restored without violating foreign key constraints.

### Step 2: Validate System Health
```bash
curl http://localhost:8000/health/ready
```
Ensure readiness reports `"database": "healthy"` and HTTP 200.

## 5. Automated Backup Schedule & Retention Policy

For production environments, schedule periodic backups using cron or an orchestration daemon:

```cron
# Take automated backup every 6 hours
0 */6 * * * /usr/local/bin/python /app/scripts/backup_db.py --output-dir /var/backups/agentsentinel

# Daily prune keeping only the last 30 days
0 2 * * * find /var/backups/agentsentinel -type f -name "backup_*.json*" -mtime +30 -delete
```

Recommended Retention Schedule:
- **Hourly backups**: Retain 24 hours.
- **Daily backups**: Retain 30 days.
- **Weekly backups**: Retain 52 weeks in secure offsite cold storage.
